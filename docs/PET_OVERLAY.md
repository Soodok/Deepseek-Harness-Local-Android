# 桌宠悬浮窗（预留能力，插件驱动）

DSH Mobile 现在预留了一套系统级桌宠悬浮窗：**安装包不包含桌宠插件，也不包含任何动画素材**。用户自行安装桥插件后，到「设置 → 扩展 → 桌面宠物」开启即可。

> **插件来源与版本声明（v1.4.21 起）**
>
> 桥插件必须是 **`@xiaopb/dsh-pet-bridge` ≥ 0.3.1**（npm 包名或 GitHub 仓库
> `https://github.com/XiaoPb/dsh-pet-bridge` 均可）。原因：
>
> - `/bubble` 从协议 v2 起强制 `X-DSH-Pet-Token`（fail-closed，缺失/不匹配 403），token 支持从 0.3.1 起才有；
> - 0.3.1 同时修了上游 `dsh-pet-bridge@0.1.0` 的真 bug —— 它 POST 不带 `Content-Length`（Node 走 chunked 编码），原生侧只按定长读 body，**必然回 400**；
> - npm 上那个无 scope 的 `dsh-pet-bridge` 只到 0.1.0（归上游作者所有，无法发新版），**装上也不通**。App 会在设置页直接标注「需 0.3.1+」并禁止开启，不会让你对着静默失败排查。
>
> 低于 0.3.1 的版本属于「已安装但不兼容」，不是「没装」——两者在设置页的提示不同。

## 1. 它是什么

- 原生侧只做「身体」：`TYPE_APPLICATION_OVERLAY` 悬浮窗、前台服务、手势、动画播放、气泡。
- 状态来源是 dsh 生态里的 `dsh-pet-bridge` 插件（纯 JS，安装在 web profile 里）。
- 桥插件监听 `turn/start`、`tool/call`、`tool/result`、`turn/end`、`agent/disposed`，向 `127.0.0.1:7779` 发送五字段 JSON：

```json
{
  "kind": "user|pre|post|stop",
  "agent_source": "dsh",
  "tool_name": "read",
  "tool_input": { "file_path": "README.md" },
  "caller_pid": 12345
}
```

协议里**没有气泡文本**。气泡由原生侧根据 `kind + tool_name + tool_input` 拼出来，只显示截断后的摘要，不显示完整参数。

## 2. 安装与开启

1. 先正常启动引擎。
2. 安装桥插件（**≥ 0.3.1**，二选一）：
   - npm：`dsh plugin add @xiaopb/dsh-pet-bridge`，或在 App 的插件中心搜 `dsh-pet-bridge`，选名为 `@xiaopb/dsh-pet-bridge` 的条目（v1.4.24 起内置目录里已用它替换上游 0.1.0 条目）；
   - GitHub：`dsh plugin add github:XiaoPb/dsh-pet-bridge`。
3. **重启引擎**（bundle 插件不会热加载）。
4. 设置 → 扩展 → 桌面宠物 → 授予「显示在其他应用上层」。
5. 打开「开启桌宠」。通知栏会出现常驻通知，点「收起来」即停止。

> 不要手工改 `profiles/web/package.json`，也不需要桌面端的 symlink 安装法。Android 壳的插件中心走的是官方 `dsh plugin --profile web add`，和现有社区插件同一条路径。

## 3. 动画包（可选）

没有动画包时，桌宠**不显示**（服务与桥接端口照常运行，设置页会提示去下载），画不出任何占位图形。想要原版 106 段动画，请自行准备 `dsh-pet-android` 的 WebP 素材包：

- 下载 `dsh-pet-android` 的 300p / 480p / 640p **zip 资源包**（2026-10-27 起只接受 zip，不再接受 APK 安装包）；
- 在「桌面宠物 → 导入动画包（zip）」里选择它；
- 导入器会从 zip 根目录（或任意一级子目录）的 `pet-config.json` + `webp/*.webp` 提取；
- 推荐 300p（约 80MB）：内存、解码、存储都更轻；480p 更适合高配设备。

**许可提醒：** 动画素材来自上游 `dsh-pet`，其许可为「允许开源使用，禁止商用」（non-commercial）。本仓库不提交、不打包这些素材；导入的是用户自己提供的文件。代码是 MIT；物理公式移植自 `dsh-pet-android`（MIT），见仓库根目录 `NOTICE`。

**导入格式硬校验**（`PetPackInstaller`）：

- 只收**标准 zip 压缩包（`.zip`）**：rar / 7z / tar.gz 等请先解压再重新打包；完整清单见
  [`docs/ARCHIVE_FORMATS.md`](ARCHIVE_FORMATS.md)；
- 先验文件头是不是 zip（`PK\x03\x04`），不是 zip 直接拒（"不是有效的 zip 文件"），不再误报"缺少 pet-config.json"；
- 每个 `.webp` 都验 RIFF/WEBP 头——改名成 .webp 的 PNG/文本一律拒（"这些文件后缀是 .webp，但不是有效的 WebP"）；macOS 打包残留（`__MACOSX/`、`._*`）不算坏包；
- 加密 zip（ZipCrypto/AES）明确拒收（"不支持加密压缩包"）；
- 失败原因全部走错误码 + 本地化文案（`pet_pack_err_*`，三语），技术串只进日志。

**空间回收**：

- 导入失败/进程被杀留下的 `.tmp-*` / `.old-*` 半成品目录：下次导入无条件清；平时 `PetPack.ensure()` 顺手扫（超过 1 小时未改动才删，不会碰正在写入的）；
- 下载缓存 `cacheDir/pet-pack/` 里与本次下载无关、超过 7 天未动过的残件，每次下载开始时清掉；
- 已安装的包不会自动删——重复导入同内容会堆出 `xxx-2` 副本，设置页「已安装的包 → 删除」可手动回收。

导入器会拒绝：路径穿越、绝对路径、超过 2000 个 entry、单文件 >50MB、总解压 >600MB、空间不足、缺少 idle/clicks 动画的包、非 WebP 内容。失败会保留旧包。

## 4. 状态映射（默认）

| 桥事件 | 桌宠表现 | 默认段 |
|---|---|---|
| `user` | 思考，循环 | a055 工作状态-思考冒泡 |
| `pre` + read/grep/search | 探索/搜索，循环 | a052 / 读取气泡 |
| `pre` + write/edit | 工作，循环 | a054 工作状态-忙碌点按 |
| `pre` + bash/shell/exec | 忙碌，循环 | a054 |
| `post` | 短促确认（1.2s） | a056 工作状态-清点归档 |
| `stop` | 庆祝（2s）后回待机 | a057 工作状态-雀跃庆祝 |
| 未来 `error` | 垂头（2.5s） | a053 工作状态-垂头叹气冒汗 |
| 空闲 | 待机呼吸 | a058 待机呼吸休闲 |

`stop` 有 1.5s 宽限，避免多 agent 的 stop 抢掉仍在工作的会话。引擎被杀时，Service 每 30s 检查一次，长时间无事件则回待机。

## 5. 手势

- 单击：Q 弹 + 随机点击回应（a077–a081）+ 点击音效（可在设置关）；
- 长按：动作菜单（待机/点击回应/动作分类、回位、翻转、设置、收起）；
- 拖动：跟手移动；
- 快速甩出：抛物线 + 撞边反弹 + 地面摩擦。

**窗口形状**：素材是 16:9 的整幅视频，角色只占中间一块（300p 包实测左右各约 30%、上 15%、下 6% 是透明）。悬浮窗按**量出来的角色矩形**开，不再按整幅画布开 —— 透明像素不吃触摸，角色也能真正贴到屏幕边缘。
量法：每段动画第一次上屏时画进 160px 小图求 alpha 包围盒，取所有播过段落的并集（左右再取镜像并集，兼容翻转朝向），按包 id 缓存，下次开服务直接用。
量不出来（首帧未就绪）时维持整幅画布，行为与老版本一致，不会把角色裁掉。

残留限制：窗口是**矩形**，角色轮廓以内的透明角（比如头顶两侧的凹处）仍算窗口区域；这是 overlay 输入模型的限制，除非用私有 API（`TOUCHABLE_INSETS_REGION`）否则无法按轮廓裁。

**放大上屏**：素材画布只有 300px（480p 包 480px），角色在素材里约 120px 宽，而窗口常常有 600px+，也就是放大 5 倍上下。`AnimatedImageDrawable` / `Movie` 自己按目标 bounds 绘制时用的是内部 Paint（**没有开位图过滤**），结果就是沿轮廓一圈 6px 的硬台阶 —— 肉眼即"锯齿"。现在改成：先把每一帧画进「素材原始尺寸」的离屏位图，再用自建的双线性过滤 Paint 放大上屏（顺带把交叉淡入的 `saveLayerAlpha` 换成 Paint alpha，每帧少一个全尺寸图层）。代价是边缘变柔和 —— 5 倍放大本就无细节可还原，想要更锐就得换更高分辨率的包或调小桌宠尺寸。

## 5.1 漫游、贴边与碎碎念

- **横向漫游**：闲置时桌宠以约 26dp/s 横向散步，走到屏幕边界自动掉头（翻转朝向）；
  拖拽/甩抛/长按菜单/一次性动作/引擎回合期间都会让路，走-停节奏随机（走 2.5–6s，停 4–11s）。
- **贴边躲藏**：松手位置在屏幕左右边缘 28dp 内会自动吸附贴边；静置 12 秒把窗口再往外挪
  半个身位，只露半边；碰一下或再拖一下立即探出（贴边位，不回退）。
- **碎碎念气泡**：内置 320 句（assets/pet/lines-default.txt，11 个情境分类），
  触发情境：开机（按时段选早晚/深夜问候）、单击、4s 内连点 3+ 次、被甩出、贴边、
  时段切换（早上 5–11 / 傍晚 17–23 / 深夜 23–5）、久置 10 分钟、闲置 5 分钟后偶尔乱弹、
  引擎工作回合偶发陪聊。全部台词共用 20 秒冷却，冷却内触发一律静默。
- **气泡样式**：自绘底板 `PetBubbleDrawable` —— 一条闭合 Path（圆角矩形 + 底部小尾巴）
  一次填充、一次描边，圆角按单行正文高度收敛成胶囊，外加 `setShadowLayer` 的柔光投影
  （该 View 走软件层渲染，硬件画布会忽略模糊）。尾巴指向**角色中线**，气泡被屏幕边缘
  夹偏时尾巴自己跟着挪，始终"指着头顶说话"。
- **气泡位置与字号**：字号 = 角色宽 × 0.075，再夹在 11~19sp；内边距/圆角/尾巴都是 em 口径，
  字号一变整套尺寸同步缩放。气泡**正文底边贴在角色头顶**（窗口顶边就是角色顶边），只有
  尾巴尖压过去 15% 尾巴高，因此不会压住动画；头顶塞不下（宠物挨着状态栏）自动翻到脚下、
  尾巴朝上。最大宽度 = min(屏宽 74%, 角色宽 × 1.35)，最多 3 行后省略。
- **台词库编辑器**（设置 → 音效与碎碎念 → 台词库）：11 个分类、一行一句编辑；
  导出/导入 JSON（SAF 文件选择器）；支持单分类恢复内置与全部恢复内置。
  用户改动落在 `filesDir/pet/lines/<cat>.txt`，内置文件永不修改。

## 5.2 动画播放与卡帧检测

播放链分两层：`PetAnimChain` 决定"现在播什么、播完接着播什么"，`PetView` 负责解码与上屏。两类历史顽疾及现在的防线：

**不再依赖 drawable 自调度**。`AnimatedImageDrawable` 通过 `Drawable.Callback` 请求重绘，
但这条自调度**偶发丢一次就永久停住**（`isRunning` 仍是 true），而且 `View` 默认的
`verifyDrawable()` 不认非背景/前景的 drawable，`invalidateDrawable` 会被整个丢掉。
现在的做法：重写 `verifyDrawable()` 接受动画槽位，并由 ticker 按 **41ms（素材帧率）主动泵帧**，
不指望 drawable 自己叫醒我们。

**一次性动画只播一遍**。`AnimatedImageDrawable.repeatCount` 是"重复次数"语义，写 1 等于播完
再重播一轮（共两遍），而链按清单时长推进 —— 动作会被截断。一次性动画统一写 `0`，
定时器与 `pet-config.json` 的段时长对齐（夹在 0.4s~30s 兜脏数据），播完**停在最后一帧**
（不清屏）再交回链。

**失败与卡帧都有人管**：
- 四类播放失败（`unavailable` / `no_asset` / 解码失败×2）不再静默：`onPlaybackError` 进日志 + 状态总线，服务侧按 slug 5s 限流；
- 解码失败**保留旧帧**不清屏（清屏 = 画面黑掉），另发一个 400ms 的跳过信号让链继续推进，链不会停摆；
- **卡帧看门狗**：每 500ms 查一次"是否 2s 没有新帧上屏"，命中先记 `stalled` 日志，再尝试自愈 —— 循环动画停摆走 `restart()`，泵帧断链走重挂 ticker；同一段最多救 2 次，救不动就放手只留日志（素材坏了无限重启只会变成"每 2 秒闪一下"）。

看门狗的判据是"**有没有在重绘**"，不是"画面有没有变化"：素材若带了 `blend=1/dispose=0`
（libwebp 默认），静止旧帧会被泵帧一直重画成越来越脏的残影，这种"有帧但不动"它看不出来
—— 那是**资源产物问题**，用 `scripts/probes/fix_webp_blend.py <pack-dir> --apply`
就地改帧标志（不重编码、秒级、幂等），配合 `scripts/probes/inspect_webp_anim.py`（帧头 dump）
与 `scripts/probes/check_webp_ghost.py`（量化合成残留）定位。

## 5.3 桥插件门禁（服务层硬拦）

桥插件没就绪时桌宠**不画角色** —— 判定在 `PetPluginDetector.bridgeGateOpen()`，设置页与服务共用一份：

- **就绪**（装了 + 进了 bundles + ≥ 0.3.1）→ 放行；
- **版本过低** → 硬拦：协议 v2 下旧插件不带 token，连上也是永远 403，开了只会让人以为"桌宠坏了"；
- **没装 / 装了没启用** → 硬拦。

> **2026-10-27 起门禁全面收紧（用户明确要求）：开启桌宠 = 硬门禁，不能跳过。**
> 曾经的「仍然开启」软旁路（`pet_allow_without_bridge` 偏好）已删除。
> 开启入口（`PetPluginDetector.canEnable()`）要求**悬浮窗权限 + 桥插件就绪 + 资源包就绪**
> 三者齐备：设置页开关在任一缺失时弹引导窗（跳权限页 / 下载资源包 / 插件中心），
> 但**不提供任何旁路**；`restoreIfEnabled()` 恢复路径用同一判定，条件不齐不拉起服务。

卡点放在 `PetOverlayService.attachPet()` 入口：`onCreate`、`onStartCommand`、`reloadPet`
三条路最后都汇到这里 —— 以前只在设置页那一个弹窗里查，`MainActivity.onResume →
restoreIfEnabled()` 和 `START_STICKY` 重建都能绕过它。被拦时（`holdForBridge`）前台服务照跑、
窗口与驱动收干净，状态里置 `bridgeMissing`：

- 通知栏显示「已暂停：桥插件未就绪」（优先于"已连接/等待"）；
- 设置页开关卡出现 warning 色提示行，点击直达插件中心；状态副标题同步变橙色，不再显示"运行中"；
- 桥插件就绪后重新开启（或点提示行走一圈插件中心回来）即恢复。

## 6. 权限、保活与排障

- 必需：`SYSTEM_ALERT_WINDOW`（用户手动授予）、前台服务通知（Android 13+ 可选授权）。
- 服务被系统回收后，只有 `pet_enabled=true` 才会 `START_STICKY` 重新拉起；用户点「收起来」或显式退出引擎则清除偏好。
- 不注册开机自启；打开 App 时按偏好恢复。
- 端口 `7779` 被占用（例如 cc-pet 正在运行）时，状态会显示「端口被占用」，桌宠仍可显示但不接收事件；停掉占用者后重新开启。
- 桥插件装了但没重启引擎 / 没进 profile bundles：状态显示「已安装，请重启引擎」。
- 厂商后台限制（小米省电策略、荣耀电池优化等）需要用户手动允许后台活动；不承诺 100% 常驻。

## 7. 安全边界

- 接收器只绑 `127.0.0.1:7779`，不暴露局域网。
- **鉴权（v1.4.21）**：`/bubble` 要求请求头 `X-DSH-Pet-Token` 等于桥 token。token 由 App 每进程随机生成（不落盘、不复用），经引擎环境变量 `DSH_PET_BRIDGE_TOKEN` 只交给引擎内的桥插件 —— 同设备第三方 App 拿不到，伪造表情/气泡的通道被关闭（照抄 AgentBridge v1.2.99 的先例，fail-closed：缺失/不匹配一律 403）。`/ping` 免鉴权，仅暴露服务存在性。
- 请求体 ≤8KB、头 ≤8KB、5s 超时、2 个 worker。
- 只解析五字段；工具摘要再截断/清洗一次；不记录完整参数。
- 动画包只写 `filesDir/pet/`，不碰 `dsh-home` / `profiles`。
- 端口 `7779` 被占用（例如 cc-pet 正在运行）时，状态会显示「端口被占用」，桌宠仍可显示但不接收事件；停掉占用者后重新开启。

> 桥插件必须使用 **`@xiaopb/dsh-pet-bridge` ≥ 0.3.1**（POST 时从 `process.env.DSH_PET_BRIDGE_TOKEN` 读 token 加 `X-DSH-Pet-Token` 头，并显式带 `Content-Length`）。上游 0.1.0 既无 token（403）也不带 `Content-Length`（400），不兼容。

## 8. 故障排查（桥插件侧）

| 现象 | 原因 | 处理 |
|---|---|---|
| 设置页显示「需 0.3.1+」，无法开启 | 装的是旧版（多半是 npm 上游 `dsh-pet-bridge@0.1.0`） | 换 `@xiaopb/dsh-pet-bridge@0.3.1+`，重启引擎 |
| 开关是开的，宠物却不见了；通知「已暂停：桥插件未就绪」 | 桥插件没装 / 没启用 / 版本过低，被服务层门禁拦下 | 设置页点提示行去插件中心装好 0.3.1+，重启引擎后重新开启 |
| 播放某段动画后画面越来越脏、角色身后拖出一团黑雾 | 素材帧标志是 blend=1（libwebp 默认），帧间叠加累积 | 资源包重编（build-webp.py 打 NO_BLEND 补丁）；存量包可用 `scripts/probes/fix_webp_blend.py --apply` 就地修 |
| 某段动画播两遍或被截断 | 旧版 `repeatCount=1` 语义（播完再重播一轮） | 已修（写 0）；若复现请带上 `log.tag.DshPetView=DEBUG` 的日志 |
| 宠物动画彻底不动 | 泵帧断链或 drawable 停摆，看门狗会先记录 `stalled` 再自愈（最多 2 次） | `adb shell setprop log.tag.DshPetView DEBUG` 复现，看 `stalled` / `heal` 日志 |
| 带 token 仍返回 `400` | 插件未带 `Content-Length`（0.1.0 的 chunked 编码） | 升级到 0.3.1+ |
| 返回 `403` | token 缺失或不匹配：插件旧版、或引擎未重启导致 token 未注入 | 升级插件 + 重启引擎 |
| 通知显示「已连接」但从不弹气泡 | 插件装了但没进 `dsh.profile.bundles`，引擎未加载 | 设置页点「重启引擎」；仍不行则重装插件 |
| 端口 `7779` 被占用 | 其他桌宠工具（如 cc-pet）在跑 | 停掉占用者后重新开启桌宠 |

`/ping` 返回的 `protocol` 字段可用于确认协议版本：`2` 表示带 token 门控的新版；`1` 表示旧 APK。

## 一、四个必须成为主角的东西（按重要性排序）

现在四个卖点被平摊在 7 个镜头里，每个都不够重。v4 要给它们各自的**高光段**。

### ① 高性能 —— 核心是「连手表都能跑」

这是全片最不可替代的一点。别家 proot 方案在 3GB 设备上起不来，我们 13 秒跑起来。

必须出现的数据（全部已实测，见 `MATERIALS.md`）：
- 旗舰真机 **3.4 秒**（一加 15T / Android 16）
- 主流中端 **5~6 秒**
- **紫光展锐手表 / 3GB 内存 → 13 秒**
- 模拟器 x86_64 / 2.5GB → 2.2~2.7 秒

**视觉上怎么炸**：不要只打数字。建议做「设备阵列」——同一秒内，一排设备图标
（旗舰手机 / 中端机 / 手表）**同时**开始启动，各自的计数器跑，最后一个是最慢的手表
跑完 13 秒时，其他早就亮了。用「差距」本身制造冲击。

手表这个意象要**具象化**（画一块小圆表盘的设备轮廓，屏幕里跑着同一个引擎 UI）。
这是全片最有记忆点的一帧。

### ② 扩展 —— 「把手机变成工作站」

21 项环境扩展（Python / JDK17 / Go / Rust / Ruby / PHP / Lua / Perl / Clang /
CMake / Git / SQLite / FFmpeg / ImageMagick / OpenSSH / Vim / ADB …）

**视觉上怎么炸**：不要让 21 个名字同时列出来（那是清单不是广告）。
建议做成「工具链汇聚」——一颗颗工具图标从四周飞入、逐个点亮，**同时**在中央的
手机模型里对应地「长」出一层能力（比如 Python 点亮时手机里出现 REPL 提示符）。
最后一行字幕：「21 项，一键装」。

**要强调的差异化**（真实、可验证）：
- 依赖闭包自动解析 + 逐包 SHA-256 校验 + **原子发布**（不会留半套环境）
- **shebang 自动修复**（Termux 包写死 `/data/data/com.termux/...`，我们装完自动改写）
- **ELF 架构断言**（装之前就验二进制架构，不会装个 arm64 到 x86_64 上）

### ③ 无障碍 —— 「AI 真的会用你的手机」

实测数据（`docs/ACCESSIBILITY.md`）：
- **单步闭环 ~1.45 秒**（点击 1.13s + 验证 69ms）
- **OCR 链 326–393ms**（此前 1370–1588ms，**4 倍提速**）
- **三层感知兜底**：无障碍树 → 视觉追踪 → 帧差验证
- 对比：脚本方案依赖固定坐标；云端方案往返 1~3 秒

**视觉上怎么炸**：这是最容易做出「科技感」的一段。建议：
- 画出手机屏幕的**骨架**（节点树叠加层），AI 的「视线」在节点间跳跃
- 一次完整闭环：**定位 → 点击 → 验证**，三段用不同颜色/节奏区分
- 关键：**验证那 69ms 要单独高亮**（因为「点了」不算成功，「变了」才算）——
  这是行家才会 appreciate 的细节
- 三层兜底做成「保险丝」意象：第一层断了瞬间切到第二层，观众看到「断了也还能跑」

### ④ 桌宠 —— 社区 PR 贡献，最有亲和力的一个

事实（`docs/pet/PET_GUIDE.md`）：
- `TYPE_APPLICATION_OVERLAY` 悬浮窗，画在**所有应用之上**
- 由桥插件 `@xiaopb/dsh-pet-bridge` 驱动：监听引擎的回合与工具调用，
  往 `127.0.0.1:7779` 发五字段事件
- 资源包制（多套素材可换、云端下载）、动画链（加权随机动作 / 翻面 / 动画驱动位移）
- 气泡台词库（六档语义，可自定义措辞）
- **24 个 Kotlin 模块**支撑

**这是一个社区贡献来的功能（PR #61），值得在片中点名。**
视觉建议：让桌宠真的「活」起来——从屏幕边缘探出来、跟着 AI 工作状态做动作、
气泡冒出台词。这是全片唯一有「情感」的一段，要放松、要有趣，节奏可以慢下来。

## 二、要新增的两个片段

### ⑤ WebUI —— 「电脑上打开手机里的引擎」

事实（`docs/LAN_WEBUI.md`）：
- 应用层反向代理，监听 **3090** 端口，不改引擎文件
- 每次开启生成**随机 6 位验证码**（大号字、点一下复制）
- 电脑浏览器访问 `http://<手机IP>:3090`，输码即用
- 手机上留常驻通知，可随时关

**视觉上怎么炸**：这个天然的「跨设备」叙事很好剪——
手机和笔记本**同时**出现在画面里，笔记本屏幕上真的出现手机里的界面。
用一条光带把两台设备连起来。字幕：「大屏编辑，小屏执行。」

## 三、视觉：要「惊艳」，不要「整洁」

v3 的问题是**太克制了**——干净、正确、但没有让人「哇」的瞬间。

### 允许并鼓励的技术手段

- **深度感**：真 3D 透视（CSS transform3d / Three.js via @remotion/three），
  设备阵列可以排成有纵深的队形
- **粒子系统**：代码汇入、工具链汇聚、AI 视线轨迹，用粒子而非硬边线条
- **光效**：体积光、辉光、扫描线、故障艺术（glitch）**克制使用**——
  每片最多 2~3 次，用在关键转折点
- **镜头运动**：推拉摇移全部用上。一部片至少要有 3 个明显的 camera move，
  而不是每个镜头都静态呈现在正中央
- **速度变化**：该快的地方要真的快（能力快闪可以用 2~3 帧一个切换），
  该慢的地方要敢停（桌宠那段慢下来）
- **声音可视化**：即使最终没音轨，也可以用波形/律动做出「有节奏」的错觉

### 仍然必须守住的

- 配色令牌不变（`layout.ts` 的 theme，深色 + 天蓝 #7DD3FC）
- 每帧代码绘制，截图只在手机框内
- 竖屏 1080×1920 安全区 230/346/65，横屏 1920×1080 安全区 54/54/96
- 所有文字 ≥36px（竖屏）/ ≥24px（横屏）
- 几何审计必须继续 0 失败

### 时长

可以放宽到 **50~60 秒**。卖点变多了，44 秒塞不下；但**不能超过 60 秒**——
短视频平台完播率会崩。

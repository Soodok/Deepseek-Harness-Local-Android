# DSH Mobile 宣传片 v4 分镜与实施计划

状态：结构方案，供实现前审阅。目标 59 秒 / 60fps / 3540 帧，双 composition；本阶段不改 Remotion 动画源码。v3 两条 MP4 保留原文件与哈希。

## 1. 创意主线与取舍

一句话主张：**完整 Agent，引擎小到手表也能承载，能力大到接通工具、手机和电脑，还有社区一起把它养大。**

观众首先记住一块真正完成启动的圆表，再记住“21 项扩展汇入手机”“点击之后还要验中”“工作时身边有桌宠”。画面以动作和结果讲述能力，数据负责落锤，不再让每一段都成为同等分量的数据卡。

四个主角分配：性能（含开场）9.5 秒、扩展 9 秒、无障碍 10 秒、桌宠 7.5 秒，共 36 秒，约占全片 61%。WebUI 4 秒、原生外壳覆盖证据 3 秒、体积三口径 9 秒、社区汇入 3.5 秒、片尾 3.5 秒，共 23 秒。对比图集中在一段，避免打断四个高光段。

比较过三条路线：

| 路线 | 优点 | 代价 / 决策 |
|---|---|---|
| **设备与能力共用一条能量主线（采用）** | 手表圆环、工具粒子、验证脉冲、WebUI 光带、社区提交都由同一条线接起来；有连续记忆点 | 需要统一设备模型、时间轴与状态同步；可用 CSS 3D + SVG 达成 |
| 全片 Three.js 电影化设备舞台 | 透视与灯光自由度高 | 字体投影尺寸、WebGL 稳定性和逐帧审计成本高；本版不以此作为必需依赖 |
| 纯真实录屏加快剪 | 真实感最直接 | 当前没有完整手表 / 无障碍 / 桌宠 / WebUI 成功录屏；不能用既有失败对话录屏冒充演示，不采用此主路线 |

## 3. 动效语言与剪辑节奏

- **主气质**：精确、轻快、有生命感。主线是锋利的科技动效；桌宠用同一缓出基底的柔性 secondary motion 放松，不突然换配色或风格。
- **统一曲线**：主要推进/落点 `cubic-bezier(0.16,1,0.3,1)`；桌宠使用阻尼 spring，过冲最多约 6%。所有状态由 `useCurrentFrame()` 确定。
- **时间单位**：6 帧为微动作单位，主要动作为 12/24/36 帧，快闪仅用 2–3 帧图形剪影。快闪不承担产品名、计量数字或免责文字阅读。
- **四次明确运镜**：A 设备队列掠移并推表；B 工具汇聚绕手机；C 验证节点推进；D WebUI 沿光带追踪并拉远。固定标题/数据不随 camera 缩小。
- **转场**：match-cut + 同色运动方向衔接，镜内图形连续；主时间线零叠场文本。通过相同圆环/路径端点连接前后镜，不回到 v2 的交叉淡入重叠。
- **强光/故障瞬间限定三处**：01 表盘扫描裂变、03 汇聚完成短光压、05 验证成功短脉冲。均局部、低占空比，不做连续全屏白闪；其他段只用稳定辉光，不再加第四个爆点。
- **节奏曲线**：02–04 蓄积能力 → 05 验证为技术峰值 → 07 跨设备展开 → 09 稳定读图 → 10 桌宠情感停顿 → 11 社区再次收束 → 12 留给入口。
- **无音轨也成立**：节拍条/波形只表现剪辑节奏，不冒充真实音频分析；本版不依赖外部音乐授权或自动生成旁白才能看懂。

## 5. 版式、安全区与运镜预算

继承 v3 的 `layout.ts` / `ui.tsx` 安全区和字号，不重新发明像素安全边距。

| 项目 | 竖屏 1080×1920 | 横屏 1920×1080 |
|---|---|---|
| 安全 insets | top230 / bottom346 / side65 | top54 / bottom54 / side96 |
| 安全内容带 | x65–1015 / y230–1574 | x96–1824 / y54–1026 |
| 章节线预留 | 46px，正文止于y1528 | 32px，正文止于y994 |
| 所有代码文字下限 | 36px，普通数值≥40 / 高亮≥48 | 24px，普通数值≥28 |
| 柱图高度 | 普通≥16 / 本作≥20 | 普通≥12 / 本作≥14 |
| 主场景预算 | 标题约240 + 主视觉约880 + 说明约130 + gap48 ≤1298px | 标题520px + gap70px + 主图区1138px，总宽1728px |

- 设备阵列竖屏先做三设备横向低高比队列，再将手表在**同一受限主视觉区域**放大；横屏做纵深斜队列。不把横屏组整体缩成竖屏导致文字低于36px。
- 工具汇聚同时只暴露少量带字工具，其余是可追溯的图形粒子；文字始终留在独立标签通道，汇聚到设备时标签先消失，不把21个名称叠进屏幕。
- 允许设备壳、光带、粒子按叙事重叠；它们属于图形合成。所有标题、数值、脚注、会话说明仍禁止非语义重叠。
- camera只作用于图形舞台。关键文字不随缩放/透视一起缩小；UI内部无需阅读的骨架只画块和线，不塞微型装饰文字。
- 不用 `overflow:hidden` 掩盖越界文字；运镜在图形区域内预先限制最大变换包络，读数帧落到确定尺寸。

## 6. 实施结构与接口

继续使用现有 React / Remotion 4.0.539、已打包字体、CSS/SVG。首选不增加依赖；确定性 SVG 粒子与 CSS 3D 已足够满足深度和叙事粒子要求。

建议新增独立 `src/v4/`，将v3场景保留为参考，不把一版表演耦进旧组件：

```text
src/v4/
  data.ts                 59秒/12镜时间表，事实来源与台词
  motion.ts               镜头轨迹、统一虚拟时钟、确定性粒子路径
  V4Promo.tsx             无重叠Sequence时间线
  components/
    CameraRig.tsx         只变换图形舞台；固定文字不受影响
    DeviceModels.tsx      手机/圆表/笔记本代码模型
    EngineSurface.tsx     多设备共用同一引擎/会话示意状态
    ToolConvergence.tsx   catalog id驱动的21颗工具粒子
    RoutedParticles.tsx   闭环、光带、提交主干共享路径组件
    PetActor.tsx          SVG鲸鱼、朝向/动作/气泡、确定性状态
  scenes/                 对应12镜，Performance/Extension/A11y/Pet独立场景
```

关键接口：

- `DeviceModels` 接受 `kind / state / progress / presentation`，屏幕由 `EngineSurface` 渲染；事实标签由外部正常流布局提供。
- `CameraRig` 接受归一化 `progress` 和 shot-specific 轨迹，只包视觉舞台，不包主张/数字。
- `RoutedParticles` 接受固定 `seed / path / count / start / duration`；不用 `Math.random`、系统时钟或CSS animation。
- `PetActor` 接受 `idle / peek / working / success` 和朝向；动作改变有预备、跟随、停稳，不做事件随机试播。
- `Facts` 每项绑定 `source / scope / display`；来源文件只作为开发证据，不把代码路径塞进产品画面。
- Composition继续保留 `DSHMobilePortrait` / `DSHMobileLandscape` 两个入口，版本升到1.3.0，时长3540帧。渲染显式输出 `-v4.mp4`，不调用会覆盖旧默认输出的脚本。

## 7. 分阶段验证与交付门槛

1. **证据固化**：为MATERIALS追加v4事实来源，写事实/时间轴契约测试，确认12镜连续、59秒、两种尺寸60fps；保存v3文件hash。
2. **先做三张关键帧**：设备阵列手表完成帧、工具汇聚落地帧、69ms验证特写；双格式用 `remotion still` 渲染并Read实际查看，先判断是否具备想要的冲击力。
3. **完成四个主角段**：每镜开头/中段/结尾各渲染3帧；镜02/03/05/07另外看运镜最大偏移帧；桌宠读2秒以上动作序列，不能只凭静帧宣布“活了”。
4. **串成59秒**：对每秒1帧共59点/格式制作分组联系表，逐页Read；原尺寸放大所有读数帧，再制作40%缩略图看可读性。
5. **审计升级**：v3审计只测普通DOM，需要补SVG文字、投影后的设备/文本边界、opacity可见性、camera极值帧、粒子与脚注关系；明确图形合成豁免对象，不对整场关闭碰撞检测。每格式3540帧，合计7080帧，0越界/非语义碰撞/字号失败。
6. **独立审查**：审事实绑定、模拟/实录标注、三条红线、桌宠条件、camera是否真有明显运动；问题修完再编码。
7. **编码与成片复检**：Windows优先并发1（v3并发4有worker停滞记录）；两条完整v4 MP4，ffprobe确认59.000s/60fps/3540帧/正确尺寸。从每条成片抽至少18帧（涵盖12镜、三体积口径、四次camera落点、手表13s、69ms、桌宠动作），Read实际查看，不能只看渲染still。
8. **记录**：`FIXES_V4.md` 记录改动、每镜证据、审计结果、ffprobe/哈希、最弱镜头；用户汇报说明最惊艳3镜的实际效果及原因。

未有v4渲染前，本文件的“惊艳”是设计意图，不是已验证成片结论。

## 8. 预期最惊艳的三镜

1. **02 设备阵列 → 手表点亮**：前面的手机先完成启动，镜头却继续向一块圆表推进；小设备最后亮起完整引擎，形成真正与产品能力相关的反差。
2. **03 21颗工具汇入手机 → 能力层生长**：每个粒子带来可见能力，运动不是装饰；从散开的工具世界落到一台能工作的手机，是一次明确的规模转化。
3. **05 从点击追到69ms验证**：镜头把通常被剪掉的“确认结果”变成主角，页面状态改变才闭环；既有科技感，又用一个具体细节解释无障碍为何可靠。

桌宠第10镜承担的是情感记忆：它用预备、探头、回应和停留让观众产生陪伴感，而不是竞争另一个高强度光效峰值。

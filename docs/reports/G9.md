## 3. 设计取舍

- **为什么只记成功的步**：失败尝试由 loop 自己重试（`onFail.retry`），写进轨迹只会让剪枝器和记忆都变脏。
- **为什么复用 verify 的 dump**：`verifyStep` 本来就要读屏判 `anyText`，把那一屏交给录制器等于
  录制开销 0；只有 `key back` 这类**无 verify** 的步才补一次 dump。
- **为什么白名单与重放器同源**：`MemoryReplay.dispatch` 只有 tap/tap_id/gesture/input/key/scroll/launch +
  noop + scroll_to + scroll_find 分支。`set_switch` / `repeat` / `pinch` / `swipe` 在 loop 里能用，
  但重放器不认 —— 这类轨迹入库就是「能召回、一跑就废」，必须在入库前拒掉。
- **为什么不给 swipe 反推方向**：`swipe.dir=up`（手指上移）≡ `scroll.direction=down`（看下面的内容），
  语义相反；自动换算是猜，猜错就是点错页。要滚动请用 `scroll`。

## 6. 追加验证（21:30 起，含三处缺陷）

### 6.1 scroll 步录制（PASS）

`/loop/run` = launch 设置 → `scroll direction=down distance=600` → key back：

```text
i=1 scroll args={"direction": "down", "distance": "600"}
LEARN: {"ok":true,"steps":3,"pruned":0,"drops":[]}
```

### 6.2 input 步：录得下、但入库必须拒（PASS）

`/loop/run` = launch → tap「Search settings」→ `input text=display` → key back，轨迹落盘：

```text
i=2 input args={"len": "7"}          ← 明文 "display" 未出现
LEARN: {"ok":false,"rejected":true,
        "reason":"input: the text is never recorded (privacy), so this step cannot be replayed (step 3)"}
```

`TracePruner.unreplayable` 新增该判定：`input` 有重放分支但永远拿不到文本（隐私只记 len），
存下来就是「命中即回落」。JVM 断言 +3（reason 含 privacy 与 1-based 下标）。

### 6.3 缺陷：保护页把 AI 困死（已修，v1.7.6）

验证 6.2 时设备停在 `com.android.settings.intelligence`（设置搜索页，属保护包），
结果**连 `/key home` 都被 403**（`{"ok":false,"error":"protected page"}`），
AI 无法自行离开，只能人手动按。保护页闸门拦的是「授权/改设置」，而
back/home/recents 只做导航，什么权限都给不了。

修法：`ProtectedPages.isNavigationKey(body)`（纯函数，JVM 断言 8 条），
`route()` 里对 `/key` + 导航键放行闸门；`enter` 不算导航（可能提交表单）。
`/tap`、`/input`、`/gesture` 等仍在保护页一律 403（实测 `/input` 仍 403）。

### 6.4 缺陷：重放器的保护页判据误伤设置首页（已修）

重放「打开设置并滚动」时，`key back` 那一步返回
`reason=protected-page: com.android.settings` —— 但设置首页根本不是保护页。

根因：`MemoryReplay` 把**整屏文本**喂给 `ProtectedPages.isProtectedFast`，
而设置首页里「Security」「Privacy」都是普通列表行，标题词规则一命中就整条记忆停摆。
桥的保护页闸门用的是 `titleBlob()`（只看顶部 25% + heading），从来没这个问题。

修法：重放器改用 `svc.titleBlob()`，与桥**同源**。整包保护（安装器/权限控制器…）
只看包名，不受影响。JVM 桩补 `titleBlob()` 签名（stub 漂移断言会兜住签名）。

### 6.5 缺陷：无 verify 的步把 afterFp 记成换页前的屏（已修）

重放「打开设置并滚动」第二步（`key back`，无 verify）判 `verify-failed`，
期望文本全是设置页的行 —— 说明录制时拍到的是**按返回之前**的屏。

修法：`MemoryRoutes.onLoopStep` 在没有 verify dump 时先
`awaitSettle(120,1500,60)` 再拍，并重读前台包（设置 → 桌面时指纹里的
`pkg:` 元素也要跟着换）。代价只落在这些没 verify 的步上。
这与 §3 里 launch 步的处理是同一类缺陷、同一套解法。

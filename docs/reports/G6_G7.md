## 3. 脚本里三个必须记住的坑

1. `am force-stop` 会**杀掉无障碍服务**，重启后必须 `settings delete` + `settings put secure enabled_accessibility_services` 重新绑定；
   直接 put 同样的值不会触发重绑（值没变），所以要先 delete。
2. 应用重启后桥 token 会变 —— 每次重启都要重新从 `/proc/<node pid>/environ` 取，拿旧 token 的请求会静默失败（返回空）。
3. `POST /task/stop` 之后**所有动作都会被「用户叫停」闸门拒绝**，下一轮开始前必须
   `POST /task/allow {"allowed":true}`（空 body 会 400 —— 这条踩过，导致连续两轮 tap 全 False）。

## 4. 已知边界

- 自动学习的签名是「包名: 首步目标 -> 末步目标」，不是人话；靠 `/memory/v2/label` 补。
  label 之后 intent 与签名不再相等，**同一任务下次会新建一条**而不是累加 pendingHits —— 当前用「精确签名匹配」换「不会把两条不同任务合并」。
  要改的话得让 label 同时写入一个稳定 `taskKey`。
- 转正只看「同签名 + 指纹 Jaccard ≥0.9」，不校验步骤是否一致；两条同签名但步骤不同的记忆会互相覆盖。

## 5. 补测：不可重放的轨迹不入库（2026-11-11 晚）

**现象**：桥把整次 `/loop/run` 记成**一步**（`loop_step`），循环内部的 tap/scroll 不进轨迹，
args 也是空的。这样的记忆存下来后，每次命中都会在重放第一步落到
`unsupported action: loop_step` → `fallback=true` 回落云端，同时 `misses+1`
（两次后降级成 suspect）—— 属于「命中即失败」的垃圾记忆。

**修法**：新增纯函数 `TracePruner.unreplayable(steps)`，在 `learn` 与自动学习两处入库前挡掉，
响应里写明原因。真正的修法是让 `LocalLoopExecutor` 把内部每一步也写进轨迹（待办）。

**真机验证（emulator-5556）**

```
POST /loop/run {"goal":"打开显示","steps":[tap Display, tap Dark theme]}
  -> ok=true totalMs=1226（内部两步都成功）
轨迹: 2 步 -> ["launch", "loop_step"]     ← 确认 loop 内部动作没进轨迹
POST /memory/v2/learn {"traceId":...}
  -> {"ok":false,"rejected":true,
      "reason":"loop_step: /loop/run 内部动作未进轨迹（第 2 步）"}
```

JVM 新增 5 条断言（普通轨迹可重放 / 空列表 / loop_step 触发 / 原因含 endpoint / 原因含 1-based 下标）。

## 1. 结论

推荐 **墨青 Ink**。现在的问题是只有两层中性灰（#141414 / #202020），蓝色只用在发送按钮上，计划、提问、思考、diff 共用同一套灰度，层次只能靠位置区分。四套方案都改了阅读底色的色温，并给每类语义单独分配颜色。按钮色只是其中一项。

### 推荐理由与代价

- **Ink**：青黑底配青绿主色，蓝色计划、琥珀提问在色相上分开；推荐依据是低饱和底色、清晰文字对比和语义区分。长时阅读的舒适感仍是设计判断，未经用户长时间阅读试验。代价是改变当前 Flutter 源码中 #3B82F6 的发送按钮颜色；beta.16 的本地 Web 构建记录不代表已发布。如须保留蓝色，可继续使用 #3B82F6/白色箭头（图形对比 3.68:1 达标）；若按钮有文字，#0B1A33/蓝底的文字对比为 4.72:1。
- **Ember**：暖色夜间方向，棕黑底与橙色主按钮有明确差异。代价是 diff 删除色和主按钮橙色色相相近，必须保留 +/− 符号及位置语义。
- **Indigo**：在四套方案中最接近现有蓝色，迁移幅度最小；蓝紫色调偏冷。长时阅读的舒适度没有经过对照试验。
- **Paper**：日间浅色方案。代价是语义色在浅色表面上只有 4.6～5.0:1，余量最小；它要求同时提供深浅两套主题，Flutter 侧的工作量最大。

所有动效都是有限次的状态过渡，没有无限循环、发光或背景动画。reduce-motion 时：HTML 用 `@media (prefers-reduced-motion: reduce)` 去掉 transition；Flutter 在 `MediaQuery.disableAnimationsOf(context)` 为 true 时用 Duration.zero。2000ms 停留照常执行，因为它控制的是信息停留时间，不是运动。

## 4. 计划状态机与定时器归属

状态：`expandedAuto`（新计划，带定时器）→ `collapsed`；`pinned`（用户手动展开）；`collapsed`。

- 定时器由 Dock 的 State 持有（单个 `Timer?`），身份键是 `(planId, generation)`。只有身份键变化才重新计时；同一计划的 steps 状态更新（例如勾选完成）不重置计时。
- 每次启动定时器先 `cancel()` 旧的，同时递增一个 token；回调里检查 token 和 `mounted`，避免快速连点时旧回调把面板收起。
- 用户点击时一律取消定时器：如果当前展开，就收起并解除 pinned；如果当前收起，就展开并设为 pinned。pinned 状态下任何状态更新都不会自动收起。
- pinned 只属于当前 `(planId, generation)`，不跨计划继承。新身份到来时清除 pinned 并重新进入 expandedAuto；理由是避免旧计划的手动选择压住新计划的首次说明。同一身份的进度更新仍保留 pinned。
- `dispose()` 时取消定时器。

预览里的对应实现：`arm()`、`clearTimer()`、`token`、`pinned`，"重放首次计划"按钮会复现 2 秒自动收起。

## 5. 提问优先级

- 待回答的提问一直显示，直到收到真实回答或取消事件，没有定时器。
- 计划与提问从上到下放在同一上下文区，占手机预览高度最多 46%，超出部分内部滚动；composer 是其下独立的固定区域。提问卡 max-height 260（低高度时 200），计划展开区 max-height 168（低高度时 72）。计划与提问不参与 flex 压缩，避免挤小 48px 触控行。
- 空间冲突时（低高度且提问区域可见），未钉住的计划立即收成单行，优先保留提问；钉住的计划仍可滚动访问。低高度来自 600px 高度断点或“低高度 360×560”按钮。首次载入、重放、提问重现与重置都使用同一优先级规则。
- 提交按钮只有在选了选项或填了自由文本后才可用。预览中的"已选择（仅预览，未提交）"只是概念状态，不会调用任何真实接口。正式实现沿用现有 QuestionCard 的 busy、草稿保留和按 requestId 清空的语义。

## 6. 子代理集成契约（建议）

- 入口放在顶栏，徽标显示真实子代理数。列表项只使用会话已经观察到的真实 agent id 和 direct-parent address，不在前端生成或推断 id。
- 能力分级：只有 `continuable` 允许发消息；`one-shot` 和未知类型只读，输入框禁用并说明原因。
- 进入子对话时把原主对话的路由压栈，返回时恢复，同时恢复主对话的滚动位置和草稿。离开子对话时注销它的订阅。
- 预览中的“预览进入对话”只切换标题并显示显式的“返回主对话”按钮，**是模拟导航，不能替代真实接线**。主对话 DOM 和草稿不被重建。真实加载、错误重试、回执和重复提交互斥由父代理实现。徽标展示 2 个活动代理，列表含 3 个代理（包括已完成），全部为标明的样例数据。

## 7. 过程内容分层

- 思考：默认折叠成"思考了 N 秒"，展开后用 think 色、13.5px 显示。
- 文件改动：摘要行显示 `+N −M 文件名`（add/del 色），展开后显示 diff，diff 容器单独 `overflow-x:auto`，正文本身不横向滚动。
- 命令：摘要行显示命令和退出码，完整输出放在展开区。HTML 中已标明“命令示例 / 示例输出（未执行）”，不代表本任务执行过 Flutter。正式实现只显示结构化 payload 的真实 exit code 和 stderr，不从自然语言推断。
- 正文直接铺在背景上，不包卡片。只有用户消息用 user 底色区分。

## 8. 360px 移动端策略

- 横向边距：正文 18px，Dock/composer 12px。正文字号 15.5/1.62。
- 顶栏 56px，标题单行省略；图标按钮 48×48。
- 所有可点元素 ≥48px：选项行、计划行、折叠行、提交/发送按钮、主题切换按钮。
- composer 圆角 22，textarea 设 `min-width:0`，最多 96px 高后内部滚动。预览底部安全留白取 `max(14px, env(safe-area-inset-bottom))`；Flutter 用 `SafeArea` / `MediaQuery.paddingOf(context).bottom`，键盘弹出时用 `viewInsets`。
- 正文是 Dock 之上的独立滚动区，所以 Dock 不会遮住正文最后一行。
- 无障碍：折叠项有 aria-expanded/aria-controls；选项置于 radiogroup，支持方向键、Home/End 与 roving tabindex。子代理面板有持续有效的 dialog 名称、Tab/Shift+Tab 焦点循环和 inert 背景；Escape、遮罩和关闭按钮可退出并恢复焦点。返回主对话为 48×48 按钮；有 focus-visible 描边。实际辅助技术行为未验收。
- 宽度 ≤640px 时预览去掉外侧留白并使用可用宽度（最大 432px），高度取 `min(740px, 100dvh)`；长正文允许断行，只有 diff/输出容器横向滚动。以上为静态策略，不是 360px 渲染结果。

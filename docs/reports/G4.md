## 3. 真 bge 实测（2026-11-11 晚补测）

环境：`POST /ext/install {"id":"llama-cpp"}` 装扩展 → 宿主机下载 `bge-small-zh-v1.5-q4_k_m.gguf`
（15,448,256 B）后 `adb push` + `run-as cat >` 落到 `files/engine/models/` → `POST /local/ensure`
返回 `modelReady=true serverRunning=true`，3085 监听。

**关键前提修复**：第一次跑真 bge 时分数与纯 hash **一模一样**，因为 `/memory/v2/upsert` 与 learn 存的是
`vector = emptyList()` —— 条目没有向量，检索只能退回字符哈希，`engine` 字段虽报 `bge` 但语义没生效。
改为入库/学习/标注三处都算 `MemoryIndex.embed(intent)`（标注时重算，否则标注只改了显示文字），
再测 `vectorDim=512`，分数才真正变。

## 4. 结论

- **降级链有效**：bge 不可用时系统仍能跑，且不会因为低分而乱执行。
- **bge 真语义生效**：词面 10/10、语义 7/10，延迟中位 44 ms（x86_64 模拟器 CPU 推理）。
- 语义命中的 score 多落在 0.55–0.78（low/mid），说明「说法完全换掉」时当前 0.6/0.3/0.1 权重偏保守 ——
  这是**有意的安全取向**：宁可让云端再规划一次，也不拿 0.5 的相似度去点屏幕。

# 探针假绿图鉴（Probe False-Green Patterns）

> 目的：本项目已经连续栽在同一类错误上 **五次**。这份文档收集它们的共同形状，
> 让写探针时能当场识别，而不是等到反向验证才发现。

## 什么是假绿

探针通过（绿），但**把被测缺陷真的改坏之后它依然通过**。判据比被测对象宽，
于是回归失效。反向验证（故意破坏 → 必须变红）是唯一可靠的检出手段。

## 五种已发生的形状

### 1. 全文件搜索冒充结构断言

**症状**：`"someApi()" in source` 通过，但那个 API 在文件里出现多次，删掉目标
那一处后别处仍命中。

**真实案例**：`getWindowsOnAllDisplays()` 在 `rootForDisplay` 与 `windowListJson`
各有一处。把 `rootForDisplay` 退回 `windows` 后，全文件断言照样绿。

**修法**：按函数体作用域断言。

```python
def fn_body(text, name):
    """按 `fun <name>(` 截出函数体，到下一个同缩进 `}` 为止。"""
    i = text.find("fun " + name + "(")
    if i < 0:
        return ""
    j = text.find(chr(10) + "    }" + chr(10), i)
    return text[i:j if j > 0 else i + 4000]
```

### 2. 锚点不唯一（`replace(..., 1)` 打错地方）

**症状**：反向验证脚本报告「变红了」，但红的不是目标缺陷 —— 替换打在了文件里
第一个同名片段上。

**真实案例**：`"if (Build.VERSION.SDK_INT < 30) return null"` 在
`DshAccessibilityService.kt` 里有 4 处（1330 / 1413 / 1617 / 2476 行）。
`replace(old, new, 1)` 改的是 1330 行那个，不在目标函数里。

**修法**：锚点必须包含足够上下文（前一行注释、缩进层级）保证唯一；替换后
断言「命中次数 == 1」。

### 3. 计数写成「存在即通过」

**症状**：文件里有**多个**同类点（多处 JSON.parse、多个入库入口），
断言只检查「至少一处正确」。

**真实案例**：`dev` 里有三处 `JSON.parse`（目录列表 / 详情 / 元数据）。
「文件里某处有 `process.exit(6x)`」对破坏一处完全无感。

**修法**：数出现次数并等值比较，或用逐行循环校验每个点。

### 4. 断言落在模板而不是产物上

**症状**：断言检查 `assets/` 里的源模板，但真正生效的是部署时注入后的产物。

**真实案例**：门脚本的 `assets/gates/*` 里没有 `/bin/bash` 分支 —— 那个分支由
`EngineConfig.applyAgentGates` 在部署时按 `guestView` 注入。断言「assets 里必须有
`exec /bin/bash`」全部失败，而断言「部署逻辑里必须有」才是对的。

**修法**：先想清楚「哪一份是最终形态」，断言落在那一份上。

### 5. 判据与被测语义不一致

**症状**：断言通过，但通过的理由与被测行为无关。

**真实案例**：幂等守卫的测试里，我先把「探索未至之境」写成
`check(!isVolatileText(...))`，而实现把它归入易变侧 —— 测试与实现互相矛盾，
却因为断言写反方向而「通过」了一次。方向必须与实现一致，否则测试自己就是假的。

**修法**：写断言前先确认实现的真实方向（读代码，不凭印象）。

## 反向验证脚本自身的三个坑

1. **替换不生效却报通过**：bash heredoc 里嵌套引号被层层吃掉，实际没替换。
   → 用 Python 写，每次替换先断言命中数量。
2. **只看关键字判红**：全绿输出里也有 `✓ 注释点名 AT_SECURE` 这类字样。
   → 按行找 `✗`，不用 `in output`。
3. **`replace(..., 1)` 只改第一处**：多处同名时改错地方。
   → 关键锚点用全局替换，或先断言 `count(old) == 1`。

## 检查清单（写探针时逐条过）

- [ ] 这个断言引用的字符串/API，在文件里出现几次？（>1 就必须按作用域或计数）
- [ ] 反向验证时，我的锚点唯一吗？命中次数是 1 吗？
- [ ] 断言的对象是源模板还是最终产物？
- [ ] 断言方向与实现一致吗？（读代码确认，不凭印象）
- [ ] 有没有「存在即通过」的地方该改成计数/逐项？

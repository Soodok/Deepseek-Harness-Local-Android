还差基础工具

rootfs 已就位，但容器里没有 /bin/bash。它是所有命令行工具与脚本的前提。

$ apk add bash curl ca-certificates

(5/5) Installing ca-certificates
OK: 9 MiB in 8 packages
✓ /bin/bash · 1.4 MB
为什么必需

Alpine minirootfs 只带 busybox。没有 bash 时，所有 #!/bin/bash 脚本、门脚本与引擎启动都会退回 busybox sh，部分语法直接失败。

为什么现在的引导不行

读 LinuxActivity.kt（1489 行）后的结构诊断

  • 六段同权重卡片：引导 → 状态 → 镜像 → 操作 → 画面 → 命令，全是同一张 bg_card，视觉上没有「先做哪一步」的动线。
  • 引导是段落文字：真实依赖链 rootfs → bash → node/工具 → 模式开关 被写成三段 \n\n 长句。
  • 状态卡与引导卡重复：一处报「状态/版本/体积/runner」，一处说「已就绪/还差点工具」，都不指向动作。
  • 模式开关埋在操作卡第 6 行：回退时用户会以为自己在用容器。
  • 命令区在页面最底：要滚三屏才敲得到命令。

方案 A · 模块台

KernelSU / Magisk 模块页结构

覆盖功能：状态 hero（状态/指纹/引擎模式）· 依赖链 checklist · 7 个镜像分三段 · 5 项操作 · 画面 5 个控制 · 环境详情 5 项 · 底部常驻终端 → sheet。

  • 引导有「已完成 / 进行中 / 待办」视觉状态，每项带就地动作
  • 模式开关升到 hero，回退时整卡转琥珀并写明原因
  • 代价：首屏密度高，需要靠分段标题撑住呼吸感

方案 B · 安装向导

Magisk 刷入流程 · 四步 stepper

覆盖功能：四步进度 · 可选镜像 · 部署/补齐日志 · 完成页四入口 · 折叠小结 · 就绪态展开完整工作区（画面 / 控制台 / 镜像 / 操作 / 环境详情 / 安装日志）。

  • 任何时刻只有一个「下一步」，引导问题解决得最彻底
  • 失败时日志与动作在同一视线内
  • 代价：熟练用户改镜像多点一层；完成页较长

方案 C · 终端面板

TUI / htop 式整页等宽

覆盖功能：STATUS 五项 · DISTRO 7 行（含 unsupported）· ACTIONS 5 键 · 部署进度条 · SCREEN 终端占位 + 4 键 · CONSOLE 历史 + 输入。

  • 终端感最强，和 Root 管理器 / Termux 用户审美同源
  • 一屏看得到状态、列表、日志
  • 代价：触屏点按区要放大到 44px；TalkBack 需另加朗读标签；中文长句在等宽下易断

方案 D · 混合（推荐）

M3 骨架 + 终端点缀 + 底部三页签

覆盖功能：工作台（hero / 依赖条 / 一句话引导 / 7 镜像 / 6 操作宫格 / 环境详情）· 画面（预览 + 4 控制 + 抓合成 + 发热提示）· 终端（历史 + 快捷命令 + 输入）。

  • 符合原生安卓开源应用观感（M3 + 底栏 + sheet）
  • 引导只剩一句，不再与状态卡重复
  • 代价：新增底栏要改导航；「画面」需独立承接现有 screenCard

方案 E · HyperOS / Miuix

仿 SukiSU Ultra 就绪页 · 超大标题 + 分组圆角卡

本轮只做就绪态；引导态沿用方案 A 的依赖链结构，仅换皮肤。

  • 38px 超大标题 + 环境副标题（HyperOS 设置页式版式）
  • 26px 圆角 hero 卡：环境图标 / 三列指标 / 引擎分段
  • 22px 分组卡 + 52px 行高 + 左侧缩进分隔线（Miuix 列表范式）
  • 底部四页签：概览 / 镜像 / 终端 / 设置
  • 配色语义：容器引擎 = 绿 #30D158；原生 Bionic = 黄 #FFD60A（浅色下自动压深），点 hero 里的分段即可看到整页换色

怎么看

  • 顶部「视图 → 整页」把手机框拉长成完整长页，方便一次看完整个信息架构。
  • 方案 D 底部三个页签是真的可点的。
  • 深链：?plan=D&status=ready&theme=dark&view=full

# 命令注册表：让 AI 把自己的脚本注册成一条命令

> 日期：2026-11-12 · 状态：设计稿（未实现）· 关联：[MODULARIZATION_PLAN.md](MODULARIZATION_PLAN.md)
> 目标：AI 写一个 `py` / `mjs` / `sh` 脚本，注册后即可像 `dev` / `scr` 一样被快速调用，
> 由宿主统一做声明、策略、审计与清理。

---

## 0. 结论

- 这是「模块化」在我们这里最合适的形态：**模块 = 声明 + 入口 + 能力申请 + 生命周期**，
  脚本就是最小模块，不需要 Gradle 子工程，也不需要可卸载 APK。
- 调用面三层：**引擎 `bin/` 里的同名 shim**（最快，AI 在 bash 里直接敲）、
  `/dev/command/*` HTTP 端点、MCP 工具（外部客户端）。
- 安全按「不可信代码」对待：解释器白名单、目录内封、哈希校验、超时杀进程组、
  能力声明 + 用户策略、全量审计；默认**不得**拿 root。

---

## 1. 为什么不是 ExtensionManager / PluginCenter

| | 扩展中心 | 插件中心 | 命令注册表（本设计） |
|---|---|---|---|
| 是什么 | 预置/可下载的工具链包（deb/rpm 层） | 引擎内的 DSH 插件（Node 包） | 一个脚本 + 一份声明 |
| 谁创建 | 官方/社区构建 | 插件作者，走插件协议 | **AI 自己**，运行期创建 |
| 生命周期 | 重（下载、依赖、校验） | 中（pnpm、插件协议） | 轻（写文件、登记、删除） |
| 适用 | 编译器/运行时 | 改引擎行为 | 一次性/高频小工具 |

三者是互补关系，不是替代。

## 2. 数据模型

目录：`files/commands/<id>/`

```
command.json     声明（宿主写入，脚本只读）
entry.py         入口脚本（AI 写入）
assets/          可选附带文件
```

`command.json`：

```json
{
  "id": "scan-apk",
  "name": "scan-apk",
  "version": 3,
  "interpreter": "python3",
  "entry": "entry.py",
  "args": [
    {"name": "path", "required": true, "desc": "APK path"},
    {"name": "deep", "flag": true, "desc": "full scan"}
  ],
  "risk": "medium",
  "capabilities": ["files.read"],
  "timeoutMs": 30000,
  "cwd": "workspace",
  "stdout": "json",
  "sha256": "…",
  "createdAt": 1762900000000,
  "updatedAt": 1762900000000
}
```

字段约束：
- `id` / `name`：`^[a-z][a-z0-9-]{1,23}$`，且不得与内置命令冲突（`dev` / `scr` / `root` / `mcp` / `psx` / `killx` / `getperm` / `grantperm` / `say` / `notify` / `media` / `loop` / `fast` / `hid` / `shz` …，以 `assets/gates/` 实际清单为准）。
- `interpreter`：白名单 `sh` / `bash` / `python3` / `node`。禁止任意路径。
- `entry`：相对 `files/commands/<id>/`，不得含 `..`、绝对路径、符号链接跳转（canonical path 校验）。
- `sha256`：入口脚本哈希；运行前校验，不匹配拒绝并提示重新注册。
- `timeoutMs`：默认 30s，上限 300s。
- `cwd`：`workspace`（默认）/ `files` / `tmp`，不开放任意目录。
- `capabilities`：声明式，运行前由授权总线校验；声明不等于获准。

## 3. 生命周期

| 动作 | 端点 / 命令 | 说明 |
|---|---|---|
| 注册 | `POST /dev/command/register` | body = 声明 + 脚本（base64 或先写文件再登记）；写入后生成 shim |
| 更新 | 同注册，`version+1` | 旧版本保留 1 份 `command.json.bak`，失败可回滚 |
| 列表 | `GET /dev/command/list` | id / name / risk / 最近运行结果 |
| 运行 | `dshcmd run <name> --args` 或 `POST /dev/command/run` | 见第 4 节 |
| 禁用/启用 | `POST /dev/command/toggle` | 禁用后 shim 仍存在但直接 exit 78（不执行） |
| 删除 | `POST /dev/command/remove` | 删目录 + 删 shim + 从索引移除 |
| 审计 | `GET /dev/command/log` | 最近 N 次运行（id/参数摘要/退出码/耗时） |

版本语义：`version` 单调递增；运行以当前版本为准；更新失败保留旧版本可用。

## 4. 调用面

### 4.1 引擎 `bin/` shim（最快）

注册时生成 `engine/bin/<name>`：

```sh
#!/system/bin/sh
# generated by dsh command registry — do not edit
exec "<interpreter 绝对路径>" "<files/commands/<id>/entry.py>" "$@"
```

AI 在 bash 里直接 `scan-apk --path /sdcard/x.apk`，不经过 HTTP。
Linux 容器模式下路径需翻译（`/dsh/...` ↔ 宿主），shim 生成时按 `GuestPaths` 写入对应前缀，
或在容器内另行部署一份；**第一版只保证原生模式**，容器模式标注限制。

### 4.2 HTTP 端点

`POST /dev/command/run` `{"name":"scan-apk","args":["--path","/sdcard/x.apk"]}`
→ `{"ok":true,"exit":0,"stdout":"…","stderr":"","ms":123}`

### 4.3 MCP 工具

由 `EndpointCatalog` 派生两个固定工具（不动态生成工具名，避免客户端缓存问题）：
`command_list`、`command_run`；`command_run` 的描述里带当前可用命令清单与风险级。

### 4.4 发现

`dev help` 末尾增加「自建命令」分组（读 `/dev/command/list`）；
`AgentContextSeed` 里的宿主说明增加一条：可用 `dshcmd list` 查看自建命令。

## 5. 安全边界

1. **不可信代码**：脚本由 AI 生成，按第三方代码对待；不以「AI 写的」为由放宽。
2. **能力声明 ≠ 授权**：运行前走授权总线（阶段 2），按 `risk` 与用户策略决定 AUTO/ASK；
   `high` 风险默认 ASK，`files.read` 之外的能力默认拒绝。
3. **不默认 root**：命令以 App uid 运行；需要 root 的命令必须显式 `"channel":"root"`，
   且仍受三档策略与命令白名单约束（复用 `Privilege`）。
4. **目录封死**：入口与附带文件必须在 `files/commands/<id>/` 内；运行前 canonical path 校验；
   符号链接一律拒绝（与备份导出「绝不跟随软链」同一条纪律）。
5. **哈希校验**：运行前比对 `sha256`；被篡改则拒绝并标记 `tampered`，等待重新注册。
6. **超时与进程组**：超时强杀整个进程组（复用 `psx`/`killx` 的进程组语义），防孤儿进程。
7. **审计**：每次运行记录 id / 参数摘要（截断，不落敏感正文）/ 退出码 / 耗时 / 是否被策略拒绝；
   审计日志本身可导出、可清空。
8. **注册入口本身要授权**：`register/remove/toggle` 需要 `control` 能力 + 用户确认（首次）；
   AI 不能通过伪造 `command.json` 绕过（宿主写入 + 启动时重扫校验）。
9. **不进入备份**：命令目录不进备份（可由 AI 重新生成），避免备份携带可执行代码。

## 6. 与「18 模块」的对应

| DSHA 模块协议 | 我们的命令注册表 |
|---|---|
| 模块身份 / 版本 / 依赖 | `command.json` 的 id / version / capabilities |
| 贡献契约（卡片/路由/动作） | 调用面三层：shim / HTTP / MCP |
| 注册、启用、停用、销毁 | register / toggle / remove |
| 能力申请声明 | `capabilities` + 运行前授权 |
| 配置 schema 与迁移 | args schema + version 单调递增 |
| 资源句柄登记与清理 | 目录 + shim + 索引，删除时统一撤销 |

区别：DSHA 的模块是**编译期** Java 组件，我们的是**运行期**脚本。前者更可控，后者更快、
更贴合「AI 自己扩展自己」的产品叙事。

## 7. 分阶段落地

| 阶段 | 内容 | 工期 | 验收 |
|---|---|---|---|
| P1 | 目录 + `command.json` + 注册/列表/删除 + shim 生成 | 2–3 天 | 注册后 bash 直调成功；删除后 shim 消失 |
| P2 | 运行端点 + 超时/进程组 + 哈希校验 + 审计 | 2 天 | 篡改拒绝、超时被杀、日志可查 |
| P3 | 授权总线接入（risk/策略/确认）+ MCP 工具 + `dev help` 分组 | 2 天 | ASK 策略下无确认不执行 |
| P4 | 设置页「自建命令」管理（列表/禁用/删除/日志） | 2–3 天 | 与注册表一一对应 |

---

## 8. 验收用例（负向优先）

1. 注册 `name=dev` → 拒绝（保留名）。
2. `entry=../../etc/passwd` → 拒绝（目录外）。
3. 脚本写入后篡改 1 字节 → 运行拒绝（哈希不符）。
4. 死循环脚本 → 30s 后进程组被杀，无孤儿。
5. `risk=high` 且策略 ASK → 无确认不执行，审计记 `denied`。
6. 删除命令后 shim 不存在，`dshcmd list` 不再出现。
7. 容器模式下调用 → 按明示限制返回错误，不静默失败。

## 9. 风险

| 风险 | 应对 |
|---|---|
| AI 生成恶意/破坏性脚本 | 能力声明 + 策略 + 审计 + 不默认 root |
| shim 与索引漂移 | 启动时重扫目录，索引为准并修复 shim |
| 命令名冲突 | 保留名清单 + 注册时校验 |
| 容器/原生路径差异 | 第一版只保证原生，容器模式显式报错 |
| 与扩展中心职责混淆 | 文档写清三者边界（第 1 节） |

## 0. 结论

1. **不与 dsh-Go 对撞大众客户端体验，不与 DSHA 拼 Ubuntu 完整性与运维存量。**
2. 我们打三件别人绕不开、且我们已有实证的事：**原生无 PRoot 的性能**、**真编译环境**、**可审计的设备自动化**；
   把「迁移成本」做成获客入口，而不是靠功能清单追赶。
3. 90 天只排 6 个交付物：先稳（v1.6.0 正式版）、再做数据可托付（自动备份 + 迁移导入）、
   设备操控凭据、远程入口、虚拟屏 go/no-go、分发内容。**不做 18/21 模块大重构。**

## 2. 对手正在做什么

### 2.1 DSHA：进入大重构期（内部讨论稿，2026-11-12）

- **新生计划 Rebirth / 代号嫩芽**：18 个逻辑模块 = 4 基础核心 + 6 能力适配 + 8 功能模块；
  模块协议、宿主核心、**能力授权核心**（可验证调用者身份、一次性派发、代次与撤销）、容器与 DSH 适配。
- 方向：Kotlin 增量用于新宿主核心、旧 Java 经适配器接入；高刷、Gecko、Root 模块管理「必须推进」；
  桌宠与对话窗口「只排单」。
- **备份恢复**：v5 私有格式 + 旧包 v1–v4 转换；当前失败是 `LEGACY_SCOPE_CONFIRMATION_REQUIRED`
  ——旧包改过名就无法判定范围，UI 没有确认入口。修复方案 A（范围确认做进 UI）+ C（文案兜底）。
- 公开面：302MB、Android 11+、仅 arm64、电脑端远程已撤下、虚拟屏仍标实验。

**判断**：重构期 1–2 个月功能速度必然下降；备份 bug 是活跃用户痛点；「能力授权核心」说明他们也在向
「可审计的设备操控」走——我们若先落地凭据与三档策略，就能守住这条叙事。

### 2.2 dsh-Go：客户端体验 + 社区运营

- 远程主机（SSH / DSHarness Remote）、原生聊天（插话、排队、过程折叠）、分享卡与 E2E 回放链接、
  桌宠、主题图标、平板重排版、插件原生 UI。
- issue 暴露技术债：升级后引擎启动失败、`runtime_upgrade_blocked:legacy_interrupted` 只能回退、
  锁屏后子进程被清理、不打扰模式探针全失败、每次读屏固定慢约 2.5 秒。

**判断**：增长引擎是社区与内容（Trendshift、论坛、QQ 群），不是工程深度；它的无障碍与引擎稳定性
正是我们的相对优势区。

## 3. 我们的真实位置（只列已验证）

**领先 / 可宣称**
- 原生 bionic 运行（无 PRoot）：启动 2.3s；容器启动 1.33s、容器层占 0.8%。
- 双 rootfs（glibc / musl）、20 套工具链、真 clang / JDK / gradle。
- Android 8+、arm64 + x86_64 双 ABI；包体比两家小 30–130MB。
- 设备能力：EndpointCatalog 62 条端点 / 路由表 125 条（11-09 对账），MCP stdio 36 工具（派生表）。
- 无障碍屏幕文档压缩 6.8x、checkedText、流式悬浮条、TTS + 离线 ASR 闭环。
- 6 种界面语言（en / zh / de / pt-BR / th / ru）。

**落后 / 必须补**
- 备份基座已有（`DataExport` zip + manifest、合并式导入），缺自动计划 / 范围选择 / 校验保留 / 跨产品迁移。
- 无远程主机连接（只有「手机当服务端」的局域网 Web UI + 内置 SSH 工作区）。
- 无虚拟屏 / 特权屏；无 ScreenLease（tap-id 仅按 viewId 查，无 TTL / 一次性 / epoch）。
- CapabilityGate 只有开关，无「每次询问」三档。
- 社区与分发基本为零；对手有官网、插件目录、论坛、QQ 群。

## 4. 三个不争

1. **桌宠 / 分享卡 / E2E 回放链接**：dsh-Go 的主场，重投入、非我们的能力结构（Kotlin 原生 + 无社交后端）。
2. **GeckoView / 多内核**：polyfill 已覆盖 Android 8 的老 WebView 场景；引入第二内核的维护成本远大于收益。
3. **18 / 21 模块大重构**：对手重构期正是我们的交付窗口；我们按真实耦合拆分，不先建空壳。
   主题皮肤、图标包、10 语言全量同样不做（ru 已入，按需再补）。

## 5. 三个必争

### 5.1 数据可托付（P0，8–10 人日）

对手的备份文档证明这是活跃痛点；我们已有导出/导入基座（`DataExport` v1 + `BackupActivity`），缺的是自动化与可验证性。

- **自动备份**：WorkManager 三种触发（每日定时 / 引擎停止后 / 变更后），保留最近 3 份已验证副本，
  SHA-256 校验，可选密码加密（比 DSHA 的 v5「无密码只校验」更强）。
- **恢复**：范围选择（full / sessions / settings / plugins）→ 只读预检 → 冲突展示 → 提交 → 回滚点；
  确认必须在只读阶段完成，禁止「失败后重放未知写操作」。
- **迁移导入（获客入口）**：支持我们旧包、DSHA v1–v5（公开格式，MIT 需署名）、裸 `.dsh` 会话目录；
  导入后逐项核对会话 / 插件 / 设置。
- **验收**：改过名的旧包也能恢复；中断后可回滚；导入成功率可测。

### 5.2 设备操控可信（P0/P1，6–8 人日）

- **ScreenLease**：30s TTL、一次性、epoch、refresh 后二次身份确认（窗口/enabled/密码/可点/文本任一变化即失效）。
- **三档策略**：自动 / 每次询问 / 禁止，per-app；敏感 App 默认「每次询问」，解码失败 fail-closed。
- **三通道确认**：通知 + 悬浮条 + Activity 并行，先点先生效，60s 超时记为「未回答」而非拒绝。
- **验收**：过期凭据必失败；换窗口后的动作必拒绝；敏感 App 默认弹确认。

### 5.3 原生性能可证明（P1，3 人日）

- 公开可复现的基准：冷启 / 热启 / 首聊 / 内存 / 包体，脚本入库，同机同版本对比两家公开包。
- 卖点从「我们快」变成「3GB 低端机也能跑，且你能量出来」。

### 5.4 远程主机入口（P1.5，2–3 人日先做最小版）

- 最小可用：WebView 连接远端 DSH（URL + token，复用局域网鉴权），入口在主页「连接电脑」。
- 进阶：基于内置 hardssh 的 SSH 隧道；暂不做完整远程文件/插件管理（dsh-Go 自己也有局限）。

## 8. 风险与纪律

- **容器真机稳定性**：刚修三处独立缺陷，需 48h soak + 机型矩阵，别急着宣传。
- **强调色重着色**：87 处静态 `@color/accent` + 88 处 `?attr/colorPrimary`，必须逐页截图 + 变异测试。
- **备份格式**：v1 就带 manifest / 版本号 / 校验 / 可扩展，避免成为下一个「旧包无法判定范围」。
- **对手反扑**：DSHA 重构完成约 1–2 个月，我们必须在窗口内拿到迁移用户；dsh-Go 体量大，不正面争流量。
- **情报纪律**：内部讨论稿只用于判断节奏与痛点；不复制代码与文档、不公开引用、不做针对性破坏。
  DSHA 为 MIT，可参考机制但需署名；dsh-Go 为 AGPL，不复制其代码。
